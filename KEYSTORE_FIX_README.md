# JARVIS BLUE MOBILE XAU/USD — Android Keystore startup repair (source patch 1.1.1)

This archive is **source code, not a compiled APK**. It modifies the user-provided 1.1.0 project without changing its application IDs or release signing materials.

## Changes

1. `KeystoreKeyManager.cipherForEncryption()` now initializes AndroidKeyStore AES-GCM **without a caller-supplied IV**. Randomized-encryption-required Android Keystore keys reject caller IVs.
2. `CipherBox.encrypt()` reads `cipher.iv` generated by the Keystore and stores it in the existing `v1.<iv>.<ciphertext>.<tag>` envelope. The envelope format and decryption logic remain compatible.
3. Decryption checks the IV length; `JarvisDatabase` no longer generates/replaces a passphrase when an existing encrypted passphrase cannot be decrypted. Initial passphrases are synchronously saved before database creation, preventing accidental loss of access to existing encrypted data.

## Windows build

1. Extract ZIP into a new folder and keep your old project as a backup.
2. Run `BUILD_DEBUG_WINDOWS.cmd` (JDK 17, SDK API 35). Or run `gradlew.bat :app:assembleDebug --no-daemon --console=plain` with JDK 17 and `local.properties` configured.
3. Confirm `BUILD SUCCESSFUL`, then inspect `app\build\outputs\apk\debug\app-debug.apk`.
4. Verify it with `apksigner` and run a normal USB installation only if device protection permits it. Do **not** disable Play Protect.
5. Capture logcat again if startup still fails. This patch targets the confirmed AES-GCM IV exception; it does not establish the absence of other bugs.

## Important

- Keep the existing app installed if its data matters. Do not clear storage or uninstall just to diagnose a crash.
- This ZIP does not contain the release keystore. It is **not** a Play Protect security clearance.
- Debug variants generally install as `com.jarvisblue.mobile.debug` alongside release builds.
- Android device runtime tests and the Gradle build have **not** been run in this environment.
